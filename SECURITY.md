# Security policy

## Report a vulnerability privately

Report security problems in Musa CAD, its websites, documentation tooling, or
fabrication tools through [GitHub's private vulnerability reporting](https://github.com/MusaCAD/MusaCAD/security/advisories/new)
or email [pranay@weberq.in](mailto:pranay@weberq.in). Include the affected repository
or website in the report. The private reporting link is hosted in the main Musa CAD
repository and can be used for any MusaCAD project.

Please keep exploit details and affected private files out of public issues and pull
requests. Ordinary bugs and feature requests belong in the affected repository's
issue tracker.

Include, where available:

- The affected version or commit, operating system, and installation method.
- Steps to reproduce, a minimal example or proof of concept, and the possible impact.
- Relevant logs with credentials and personal information removed.

Share only files you have permission to share. Use a small example
instead of a customer's drawing or private model whenever possible.

## Updates and disclosure

Fixes target the current development branch and the latest stable release of the
affected project. Older versions may not receive the fix. Preview
builds are still under development; reports about them are welcome. For the websites,
report against the current deployment and include the page URL and date.

The maintainer reviews reports. There is no fixed response or repair deadline.
Timing depends on the problem, the information available, and the time available to
work on it. Progress and plans for a public announcement are discussed privately
with the reporter. Reporters are credited with their permission.

See the [application security policy](https://github.com/MusaCAD/MusaCAD/blob/main/SECURITY.md)
for details specific to drawing files, converters, and application releases.
